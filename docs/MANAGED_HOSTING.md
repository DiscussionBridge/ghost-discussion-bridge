# Managed Ghost hosting

The current V4 integration runs one external adapter service with its own HTTPS origin. Ghost keeps its native public/Admin origins and current Admin integration. No customer Ghost custom route, second bridge engine or remote operator service is required by this implementation.

Use the common [installation preparation](INSTALLATION.md) with the hosting owner's approved protected credentials and actual native permission scope. If code-injection settings cannot be written through the existing integration, use the returned manual Site Footer step. Preserve unrelated theme/injection/settings and take the exact protected native backup before changes. Do not increase native permissions as an automatic response to a forbidden request.

The host must allow the selected native/webhook/public paths and trusted HTTPS endpoints. Exact installed Ghost payloads, theme hooks, Admin HTML-to-native transformations, forum sessions, ownership/CAS and anonymous public fragment readback require real-host qualification. A successful local preparation or mock request does not establish them.
