Use Node 22 or newer on a Linux adapter host with executable `/usr/bin/flock` and a dedicated non-root service account. Create the protected native Ghost Admin integration key, signed webhook secret and scoped V4 Content Connection credentials through their existing owner interfaces. Copy `adapter.env.example` into the protected directory, set actual origins/paths and verify native permission scope. The common installer uses the adapter origin for same-origin operator access.

## Prepare and activate deliberately

```sh
npm run prepare:install -- --config /srv/discussionbridge-ghost/private/adapter.env --output /srv/discussionbridge-ghost/prepared-install-1 --user discussionbridge_ghost

Partial output remains inspectable. Preparation does not activate services, edit native settings/state, call the forum/Ghost, or replay pending work.

On the actual host, install the locked production dependencies using `npm ci --omit=dev --ignore-scripts --no-audit --no-fund` with an explicitly selected cache. Use the packaged browser assets; rebuilding them is a development step. Verify service-account read permissions and state-directory write permissions. Install the prepared unit/proxy, configure trusted TLS and compression, check host syntax and then deliberately start the service. Confirm its prepared health address.

Ordinary destruction retention of `previous.id` was not established by the retrieved source; an ID-less notification remains unsupported. Capture and verify the installed version's real deletion/unpublish payload and registrations before native qualification. Genuine native facts can withdraw an accepted binding, not reactivate it. ## Protected backup and bounded restore

Before an authorized native theme/settings/runtime change, create a dated owner-only backup outside the runtime and web root, such as `/srv/discussionbridge-ghost/backups/<UTC-stamp>/` (directory700/files600 on Linux, equivalent owner-only workstation controls). Record exact Ghost public/Admin origins, native version, active theme identity/version, runtime/contract pins, UTC time and byte count/SHA-256 for every file. The theme archive does not include persistent adapter state.

1. Use the installed Ghost Admin native export controls to save Content & settings JSON, exact active theme ZIP, `routes.yaml` and redirects. Record any unavailable export explicitly.
2. Save the entire Site Header/Footer as separate UTF-8 files, including unrelated injection, ordering and exact asset URLs. An empty field is an explicit empty file. Save each affected native post/page's exact ID/URL and both per-item injection fields.
3. Record exact custom theme options, logo/icon/accent/cover, primary/secondary navigation labels and URLs, social links, membership/Subscribe settings, native comments settings/prompts and referenced custom assets. A theme ZIP alone is insufficient.
4. Verify exact site/theme identity and private inventory hashes. Keep exports/settings/injection/inventory out of public assets, packages and the operator page. Unrelated member/analytics exports are not required for this backup.

For an authorized restore, stop scheduled/manual native writes and save the currently affected theme/settings first. Select the exact saved site's inventory and verify hashes. Upload/activate its saved native theme, then restore recorded affected settings and entire injection fields, per-item fields by exact native ID, and routes/redirects only when part of the authorized rollback. Resume only after actual restore checks; these instructions are not executed backup/restore evidence.
